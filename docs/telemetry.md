# телеметрия и API

телеметрия – это игровые данные, которые мод передаёт веб-сервису автоматически. веб-сервис принимает их, проверяет, сохраняет нужную историю и отдаёт браузеру готовые ответы. по тому же каналу проходят Map Ping из игры в браузер и из браузера в игру.

## поток мода

мод открывает порт `server.telemetry_port` на адресе `server.telemetry_host` и ждёт соединение. Python-клиент подключается к нему по TCP – сетевому соединению между двумя программами. после подключения мод отправляет данные. каждая строка JSON содержит одну запись; такой формат называется JSONL. поле `schemaVersion: 1` говорит, по каким правилам читать поля записи. в записи находятся состояние сервера, мира, игроков, NPC и объекты карты. Python-клиент автоматически пробует подключиться снова после обрыва. некорректную строку он пропускает и продолжает читать следующие.

у каждой полной записи (snapshot, то есть снимка состояния на этот момент) есть номер `snapshotId`. когда Python-клиент успешно прочитал и сохранил снимок, он возвращает подтверждение ACK – короткое сообщение, что запись принята: `{"ackSnapshotId":123}`. событие смерти получает собственный `id`, потому что оно может случиться между двумя снимками. мод повторяет неподтверждённые события и удаляет их из очереди только после ACK. срок хранения меток задаёт `storage.death_retention_seconds`; `0` означает хранить без автоматической очистки.

игроки и NPC передают направление, взятое из `Player.direction` и `NPC.spriteDirection`, чтобы браузер мог правильно отразить спрайт. необязательное поле `respawnPending` сообщает, что игрок ещё мёртв или его координаты после возрождения не успели измениться. пока поле `true`, карта не рисует обычный маркер игрока на старой точке, но оставляет крест смерти.

Payload – это содержимое одной записи, которую отправляет мод. для совместимого изменения добавляйте необязательные поля: старый получатель сможет их пропустить. если меняется смысл или тип существующего поля, поднимите версию схемы и на время обновления научите получателя читать старую и новую версии. не включайте в сообщения пароли, токены или другие секреты.

## HTTP endpoints

HTTP – обычный способ, которым браузер просит у сервера страницу или данные. `GET` читает данные, `POST` отправляет их на сервер, `DELETE` удаляет указанные данные. текст после `?` – параметры запроса: например, `x=10&y=20` означает координаты тайла. координаты `x` и `y` в этой таблице измеряются в игровых тайлах.

в адресах таблицы `id` обозначает ID игрока, `world` – имя мира, `days` – число дней истории, а `since` – отметку, с которой нужно получить только более новые изменения. Feature flag – переключатель, который сообщает интерфейсу, доступна ли функция.

| Endpoint                                                   | назначение                                                       |
| ---------------------------------------------------------- | ---------------------------------------------------------------- |
| `GET /api/status`                                          | сводное состояние сервера, игроков, боссов и истории             |
| `GET /api/world-map`                                       | метаданные и слои без полных пиксельных чанков                   |
| `GET /api/world-map?tiles=0`                               | совместимый полный JSON карты с пиксельными чанками              |
| `GET /api/world-map?since=...`                             | дельта обновлений карты                                          |
| `GET /api/world-map/tile-info?x=...&y=...`                 | локализованное описание блока/стены                              |
| `GET /api/world-map/exploration?id=...&world=...`          | изображение исследования игрока                                  |
| `POST /api/world-map/import-player-map?id=...`             | импорт `.map` со страницы debug; объединяет новые открытые тайлы |
| `POST /api/world-map/export-player-map?id=...`             | экспорт `.map` из сохранённой информации                         |
| `DELETE /api/world-map/import-player-map?id=...&world=...` | очистка только импортированной части карты                       |
| `GET /api/resource-history?days=...`                       | история ресурсов сервера                                         |
| `GET /healthz`                                             | локальная проверка доступности HTTP сервера                      |
| `GET /api/site-config`                                     | Feature flags интерфейса                                         |

статические файлы интерфейса (CSS, JavaScript и постоянные картинки) находятся в `/assets/`. изображения игроков, NPC и боссов выдаются отдельными адресами API из каталога данных.

чтобы проверить адрес вручную, открой его в браузере или отправь запрос из командной строки. начни с `/healthz`: успешный ответ означает, что HTTP-сервис запущен. но это ещё не значит, что мод подключился и карта получена. для этого открой `/api/status` и `/api/world-map`.
