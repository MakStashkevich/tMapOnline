# серверний мод tMapOnline

Мод називається `tMapOnline`. Він запускається всередині серверного tModLoader; гравцям не потрібно встановлювати його окремо. Мод передає ігрові дані вебсервісу й доставляє Map Ping в обох напрямках.

## що робить мод

Мод не малює карту й не запускає сайт. Він читає ігрові дані — наприклад, поточну позицію гравця — та надсилає їх застосунку tMapOnline. Застосунок зберігає дані й показує їх у браузері. Map Ping також працює в обидва боки: позначка з браузера з’явиться в грі, а позначка з гри — у браузері.

## призначення та межі

Мод і tMapOnline обмінюються повідомленнями через TCP-з’єднання на адресі `127.0.0.1`. Це адреса самого комп’ютера; зовнішні пристрої до цього порту не підключаються. Кожне повідомлення записане окремим рядком JSON. Мод не є вебсервером і не змінює параметри браузера.

Ігрові об’єкти безпечно читати й змінювати лише під час ігрового циклу, коли tModLoader оновлює світ. Для мережевих задач мод використовує вже підготовлений текст повідомлення, а не звертається до світу з іншої задачі.

`TMapOnlineSystem` керує запуском і зупинкою моду. Він підключає обробники ігрових подій, запускає інші частини моду, регулярно готує snapshot (знімок поточного стану), приймає Map Ping і закриває з’єднання під час зупинки.

| Обов’язок                                                             | Компонент                                          |
| --------------------------------------------------------------------- | -------------------------------------------------- |
| TCP listener, клієнти, JSONL, підтвердження snapshot і вхідні команди | `TelemetryStreamServer`                            |
| Знімки NPC і сутностей світу                                          | `WorldEntitySnapshotBuilder`                       |
| Зовнішній вигляд гравця та експорт текстур моду                       | `PlayerAppearanceSnapshotBuilder`                  |
| Сканування карти й зміни RGB/RGBA тайлів                              | `WorldMapScanner`, `MapTileDataCapture`            |
| Назви тайлів/стін і локалізація                                       | `MapTileNameCatalog`                               |
| Виявлення відкритої ділянки карти гравця                              | `PlayerMapChangeRevealer`                          |
| Ванільні прапорці перемог і застарілі лічильники                      | `BossProgressSnapshotReader`, `BossVictoryTracker` |
| Окрема інтеграція з Calamity                                          | `CalamityBossProgressAdapter`                      |

У таблиці вказано відповідальність кожного класу. RGB — червоний, зелений і синій кольори пікселя. RGBA також містить прозорість. `CalamityBossProgressAdapter` потрібен лише для сумісності з Calamity; решта логіки прогресу босів від нього не залежить.

Назви в таблиці збігаються з вихідним кодом. Під час роботи зі світом залишай читання й зміну ігрових об’єктів усередині ігрового циклу. Мережеві задачі можуть працювати окремо, але лише з уже підготовленими повідомленнями.

## передавання та надійність

- Типово listener (програма, що очікує мережеве з’єднання) слухає лише `127.0.0.1:38762`; параметри: `server.telemetry_host` і `server.telemetry_port`.
- Знімки передаються як JSON Lines, версія схеми `1`. Кожен рядок містить `snapshotId`; tMapOnline підтверджує отриманий snapshot тим самим TCP-з’єднанням.
- Події смерті мають незмінні ID, повторно надсилаються до підтвердження й обмежуються `storage.death_retention_seconds`.
- Клієнт tMapOnline перепідключається після розриву. Listener зберігає останній стан, щоб новий клієнт одразу отримав актуальний snapshot.
- Web Map Ping надсилається як команда з координатами тайлів; мод розсилає його підключеним гравцям. Ігрові Map Ping повертаються як події з координатами тайлів.
- Налаштування відображення браузера модові не передаються. Інтервали та напрямки пінгів задаються конфігурацією запуску сервера.

Важливо не переплутати напрямок з’єднання: мод відкриває порт і чекає, а Python-сервіс підключається до нього. Після підключення обидві сторони можуть надсилати повідомлення: сервіс — Map Ping і підтвердження, мод — нові знімки та ігрові події.

Схему й endpoints описано в [telemetry.md](telemetry.md). Якщо поле змінює значення або тип, використовуй нову версію схеми та перехідний період сумісності; не змінюй версію 1 непомітно.

## збірка

Команду потрібно виконувати з кореневої папки проєкту. У macOS шлях до встановленого tModLoader можна задати змінною `TML_ROOT`:

```sh
TML_ROOT="/path/to/tModLoader" python3 tools/build-mod.py
```

Заміни `/path/to/tModLoader` на шлях до встановленої гри. Скрипт збере C#-проєкт і збереже готовий пакет у `dist/tMapOnline.tmod`. Для збірки використовується окрема тимчасова папка, тому параметри профілю не змінюються. Скрипт не встановлює мод і не змінює файли працюючого сервера. Версія tModLoader для збірки має збігатися з версією сервера.

Щоб сервер побачив мод, скопіюй `.tmod` до папки `Mods` його профілю й додай ID у `Mods/enabled.json` — список увімкнених модів. Мод завантажиться під час наступного запуску сервера. Перед цим переконайся, що гравці вийшли, щоб не переривати їм гру.

## зміни моду

1. Знайди потрібний обробник події в `TMapOnlineSystem`. Якщо логіки там забагато, винеси її в окремий клас з одним зрозумілим завданням.
2. Простеж повідомлення повністю: хто його надсилає і хто отримує в Python-сервісі.
3. Читай Terraria API в ігровому циклі. Мережевій задачі передавай уже підготовлене повідомлення.
4. Для важливої події додай унікальний ID і повторне надсилання до підтвердження сервісом.
5. Збери мод командою `python3 tools/build-mod.py` для потрібної версії tModLoader.
6. Не копіюй `.tmod` у профіль працюючого сервера й не перезапускай його без окремого запиту на встановлення та запуск.

Обробник — це код, який запускається у відповідь на подію гри, наприклад зміну блока. Унікальний ID дає сервісу змогу розпізнати вже прийняту подію, тому повторне надсилання не створить дублікат.
