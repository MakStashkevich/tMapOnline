# конфігурація та розділи вебінтерфейсу

цей документ пояснює серверні параметри. YAML — текстовий формат із відступами: пробіли показують, до якої групи належить параметр. Серверна конфігурація визначає, які дані збирати й які функції дозволити. Вона спільна для всіх відвідувачів. Масштаб і видимість шарів кожен браузер зберігає окремо в `localStorage`.

Файл читає `tmaponline/config.py`, де параметри перевіряються перед запуском. Якщо параметр пропущено, tMapOnline використовує типове значення. Після редагування перезапусти сервіс, інакше він продовжить працювати зі старими параметрами.

```yaml
site:
  world_map:
    route_history_days: 7 # Період історії маршрутів у днях (1–365)
  pages:
    world_map: { enabled: true }
  sections:
    world: true
    players: true
    bosses: true
    server: true
    activity: true
  modules:
    world_map.exploration: true
    world_map.entities: true
```

У прикладі показано групу `site` — налаштування вебкарти та розділів. У файлі також є групи `storage` і `telemetry`. Значення після двокрапки задає стан параметра: `true` вмикає можливість, `false` вимикає. Число `7` означає, що карта запитуватиме маршрут за останні сім днів. Зберігай пробіли на початку рядків: відступ визначає групу параметра.

Коли в картці гравця ввімкнено «Історія маршруту», карта автоматично запитує збережені точки за період `site.world_map.route_history_days`. Укажи число від 1 до 365.

Нижче наведено налаштування строку зберігання та частоти оновлень. Телеметрія — це дані, які мод автоматично надсилає сервісу під час гри.

```yaml
storage:
  death_retention_seconds: 3600 # 0 — зберігати смерті без обмеження
  event_retention_seconds: 2592000 # 30 днів; 0 — без обмеження строку
  event_max_entries: 5000 # Максимальна кількість подій
telemetry:
  player_position_interval_ticks: 6 # Позиції гравців, 6 тіків ≈ 100 мс
  entity_interval_ticks: 6 # NPC, боси, монети й пілони
  map_capture_interval_ticks: 30 # Кольорові дані карти біля гравців
  map_tile_update_interval_ticks: 1 # Змінені тайли й стіни, зокрема після вибухів
  map_pings_from_players_to_web: true # Показувати на карті ігрові пінги
  map_pings_from_web_to_players: true # Надсилати гравцям пінги з вебкарти
  initial_world_scan_enabled: true # Повне сканування світу під час запуску tMapOnline
  world_scan_interval_ticks: 1 # Пауза між чанками сканера
  browser_live_poll_interval_ms: 50 # Інтервал легкого запиту актуальних даних
  browser_overview_poll_interval_ms: 250 # Оновлення під час огляду всієї карти
  browser_map_poll_interval_ms: 5000 # Інтервал отримання оновлень карти
  browser_debug_poll_interval_ms: 1000 # Інтервал карти з відкритими налаштуваннями debug
```

Строк очищення застосовується і до вже збережених смертей. Для кожної смерті мод надсилає незмінний ID і чекає підтвердження Python-сервісу. Якщо з’єднання перерветься, подія залишається в черзі й надсилається повторно.

Журнал подій автоматично очищується під час запуску й після кожного нового запису: спершу видаляються події старші за `storage.event_retention_seconds`, потім залишаються лише останні `storage.event_max_entries`. Значення `0` вимикає очищення за строком, але обмеження кількості продовжує діяти.

Частина інтервалів указана в ігрових тіках. Тік — один крок гри; за 60 тіків на секунду шість тіків тривають приблизно 100 мілісекунд. tMapOnline передає ці значення моду. Інтервали браузера вимірюються в мілісекундах: 1000 мс — одна секунда. Велику карту браузер завантажує окремо, а позиції, об’єкти й невеликі зміни блоків отримує через `/api/world-map/live`, тому йому не потрібно щоразу завантажувати всю карту.

Усі параметри й типові значення перелічені в `config.example.yaml`. Шлях до робочого файлу передають через `--config`, наприклад: `tmaponline --config config.local.yaml serve`.

| Ключ                                          | Призначення                                                                                                       |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `site.pages.world_map.enabled`                | Вмикає вебкарту tMapOnline.                                                                                       |
| `site.sections.*`                             | Вмикає розділи світу, гравців, босів, сервера й активності. Дані завантажуються при відкритті розділу.            |
| `site.modules.world_map.*`                    | Вмикає шари карти: дослідження, маршрути, гравців, сутності, монети, пілони, точку появи, підказки й діагностику. |
| `storage.death_retention_seconds`             | Час зберігання позначок смерті в секундах. `0` вимикає автоматичне очищення. Типове: 3600.                        |
| `storage.event_retention_seconds`             | Строк зберігання подій журналу в секундах. `0` вимикає очищення за строком. Типове: 2592000 (30 днів).            |
| `storage.event_max_entries`                   | Максимальна кількість останніх записів журналу. Типове: 5000.                                                     |
| `telemetry.player_position_interval_ticks`    | Частота позицій гравців в ігрових тіках. Для локального сервера — `1`.                                            |
| `telemetry.entity_interval_ticks`             | Частота NPC, босів, монет і пілонів у тіках. Для локального сервера — `1`.                                        |
| `telemetry.map_capture_interval_ticks`        | Частота захоплення кольорових даних карти біля гравців.                                                           |
| `telemetry.initial_world_scan_enabled`        | Вмикає повне початкове сканування світу. Вимкни, щоб перевіряти оновлення карти від переміщень і змін тайлів.     |
| `telemetry.world_scan_interval_ticks`         | Частота обробки чанків сканером світу.                                                                            |
| `telemetry.map_tile_update_interval_ticks`    | Частота надсилання змінених тайлів і стін. Хуки відстежують руйнування, встановлення та вибухи.                   |
| `telemetry.map_pings_from_players_to_web`     | Надсилає ігрові пінги на вебкарту.                                                                                |
| `telemetry.map_pings_from_web_to_players`     | Надсилає пінги вебкарти гравцям сервера.                                                                          |
| `telemetry.browser_live_poll_interval_ms`     | Інтервал компактних запитів браузера. Типове 50 мс для плавного руху позначок.                                    |
| `telemetry.browser_overview_poll_interval_ms` | Інтервал актуальних запитів при віддаленій карті. Позначки рухаються кроками, а не покадрово. Типове 250 мс.      |
| `telemetry.browser_map_poll_interval_ms`      | Інтервал отримання чанків карти браузером. Поточне значення — 5000 мс.                                            |
| `telemetry.browser_debug_poll_interval_ms`    | Інтервал оновлення карти з відкритими налаштуваннями debug. Поточне значення — 1000 мс.                           |

Якщо сторінку вимкнено, її адреса поверне `404` — сторінка недоступна. Вимкнений розділ зникає з меню й не завантажує дані. Вимкнений шар не малюється. Щоб додати шар, задай його типове значення, зареєструй його в `tmaponline/web/src/core/modules.ts` і додай опис сюди. Параметри, які користувач перемикає в браузері, до цього YAML-файлу не записуються.

## збірка інтерфейсу

Редаговані файли вебінтерфейсу лежать у `tmaponline/web/src`: логіку написано на TypeScript, а зовнішній вигляд — у SCSS усередині `styles`. Для збірки виконай:

```sh
npm ci
npm run format
npm run check:web
```

Збірка створює мініфіковані ES-модулі й CSS у `tmaponline/web/assets`; Python роздає їх у робочому середовищі без Node.js. Розділи карти, гравців, босів, сервера й активності залишаються окремими динамічними чанками зі своїми CSS-файлами.

`npm ci` встановлює версії інструментів із lock-файлу. `npm run format` форматує вихідні файли за правилами проєкту. `npm run check:web` перевіряє вебкод і збирає інтерфейс. Результат потрапляє до `tmaponline/web/assets`; це готові файли збірки. Редагуй вихідний код у `src` або ресурси в `static`.
