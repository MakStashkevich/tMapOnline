# телеметрія та API

Телеметрія — це ігрові дані, які мод автоматично надсилає вебсервісу. Сервіс приймає їх, перевіряє, зберігає потрібну історію та повертає браузеру готові відповіді. Тим самим каналом передаються Map Ping із гри в браузер і з браузера в гру.

## потік даних моду

Мод відкриває порт `server.telemetry_port` на адресі `server.telemetry_host` і чекає з’єднання. Python-клієнт підключається через TCP — мережеве з’єднання між програмами. Після підключення мод надсилає дані. Кожен рядок JSON містить один запис; цей формат називається JSONL. Поле `schemaVersion: 1` показує, за якими правилами читати запис. У ньому міститься стан сервера, світу, гравців, NPC та об’єктів карти. Після обриву Python-клієнт автоматично пробує з’єднатися знову. Некоректний рядок він пропускає й читає наступні.

Кожен повний запис (snapshot, знімок стану на цю мить) має номер `snapshotId`. Після успішного читання й збереження Python-клієнт повертає ACK — коротке підтвердження, що запис прийнято: `{"ackSnapshotId":123}`. Подія смерті має власний `id`, оскільки може статися між знімками. Мод повторює непідтверджені події й видаляє їх із черги лише після ACK. Строк зберігання позначок задає `storage.death_retention_seconds`; `0` означає зберігання без автоматичного очищення.

Гравці й NPC надсилають напрямок із `Player.direction` і `NPC.spriteDirection`, щоб браузер міг правильно віддзеркалити спрайт. Необов’язкове поле `respawnPending` означає, що гравець ще мертвий або його координати після відродження ще не змінилися. Поки значення `true`, карта не показує звичайну позначку гравця на старому місці, але залишає хрест смерті.

Payload — це вміст одного запису, який надсилає мод. Для сумісної зміни додавай необов’язкові поля: старий отримувач може їх пропустити. Якщо змінюється значення або тип наявного поля, збільш версію схеми й на перехідний час навчи отримувача читати обидві версії. Не додавай у повідомлення паролі, токени чи інші секрети.

## HTTP endpoints

HTTP — звичний спосіб, яким браузер запитує сторінку або дані в сервера. `GET` читає дані, `POST` надсилає їх, `DELETE` видаляє вказані дані. Текст після `?` — параметри запиту: наприклад, `x=10&y=20` задає координати тайла. У цій таблиці координати `x` та `y` вимірюються в ігрових тайлах.

У шляхах таблиці `id` — ID гравця, `world` — назва світу, `days` — кількість днів історії, а `since` — позначка, від якої потрібно отримати лише нові зміни. Feature flag повідомляє інтерфейсу, чи доступна функція.

| Endpoint                                                   | Призначення                                                           |
| ---------------------------------------------------------- | --------------------------------------------------------------------- |
| `GET /api/status`                                          | Зведений стан сервера, гравців, босів та історії.                     |
| `GET /api/world-map`                                       | Метадані й шари без повних піксельних чанків.                         |
| `GET /api/world-map?tiles=0`                               | Сумісний повний JSON карти з піксельними чанками.                     |
| `GET /api/world-map?since=...`                             | Дельта оновлень карти.                                                |
| `GET /api/world-map/tile-info?x=...&y=...`                 | Локалізований опис блока або стіни.                                   |
| `GET /api/world-map/exploration?id=...&world=...`          | Зображення дослідження гравця.                                        |
| `POST /api/world-map/import-player-map?id=...`             | Імпорт `.map` зі сторінки debug з об’єднанням нових відкритих тайлів. |
| `POST /api/world-map/export-player-map?id=...`             | Експорт `.map` зі збережених даних.                                   |
| `DELETE /api/world-map/import-player-map?id=...&world=...` | Очищення лише імпортованої частини карти.                             |
| `GET /api/resource-history?days=...`                       | Історія ресурсів сервера.                                             |
| `GET /healthz`                                             | Локальна перевірка доступності HTTP-сервера.                          |
| `GET /api/site-config`                                     | Прапорці функцій інтерфейсу.                                          |

Статичні файли інтерфейсу (CSS, JavaScript і постійні зображення) розміщені в `/assets/`. Зображення гравців, NPC і босів віддаються окремими адресами API з каталогу даних.

Щоб перевірити адресу вручну, відкрий її в браузері або надішли запит із командного рядка. Почни з `/healthz`: успішна відповідь означає, що HTTP-сервіс працює. Але це не підтверджує підключення моду чи отримання карти. Для цього відкрий `/api/status` і `/api/world-map`.
