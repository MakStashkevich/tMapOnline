# серверный мод tMapOnline

Дата проверки: 2026-11-11. Mod ID и имя сборки — `tMapOnline`. Мод работает только на сервере; подключившимся игрокам не требуется его скачивать.

## зачем я сделал мод

веб-карта должна была показывать не только снимок мира, но и то, что происходит во время игры. сначала это был сервер без модов, а потом мы перешли на tModLoader. я добавил `tMapOnline`, чтобы сервер мог передавать странице карту, позиции игроков, NPC, боссов и другие игровые данные. сам мод не рисует веб-страницу: он собирает состояние на стороне игры и отправляет его локальному сервису.

ещё мне хотелось общаться с друзьями через карту, не заходя самому в Terraria. поэтому мод умеет принимать Map Ping из веба и передавать их игрокам, а игровые отметки отправлять обратно в веб-карту.

## назначение и границы

Мод передаёт tMapOnline данные к данным Terraria через loopback TCP JSONL. Он не является веб-сервером и не управляет браузерными настройками. tModLoader остаётся владельцем игрового мира: чтение/запись игровых объектов выполняются на игровом потоке, а фоновые socket-задачи работают с уже сериализованными строками и очередями команд.

Главный lifecycle/composition root — `TMapOnlineSystem`. Он подключает хуки tModLoader, создаёт collaborators, собирает snapshot с настроенной частотой, применяет входящие команды Map Ping и освобождает ресурсы при выгрузке мода.

| Обязанность                                                             | Компонент                                          |
| ----------------------------------------------------------------------- | -------------------------------------------------- |
| TCP listener, клиенты, JSONL, подтверждение snapshot и входящие команды | `TelemetryStreamServer`                            |
| Снимок NPC и сущностей мира                                             | `WorldEntitySnapshotBuilder`                       |
| Выгрузка внешнего вида игрока и текстур мода                            | `PlayerAppearanceSnapshotBuilder`                  |
| Сканирование карты и изменения RGB/RGBA тайлов                          | `WorldMapScanner`, `MapTileDataCapture`            |
| Названия тайлов/стен и локализация                                      | `MapTileNameCatalog`                               |
| Обнаружение области карты игрока                                        | `PlayerMapChangeRevealer`                          |
| Ванильные флаги побед и legacy-счётчики                                 | `BossProgressSnapshotReader`, `BossVictoryTracker` |
| Специфичная интеграция Calamity                                         | `CalamityBossProgressAdapter`                      |

Эта таблица следует текущим классам исходников. Перед переносом игровой логики в фоновые задачи нужно проверить thread-affinity API tModLoader.

## транспорт и надёжность

- По умолчанию listener слушает только `127.0.0.1:38762`; настройки сервера: `server.telemetry_host` и `server.telemetry_port`.
- Снимки — JSON Lines, schema version `1`. Каждая строка содержит `snapshotId`; tMapOnline подтверждает принятый snapshot тем же TCP соединением.
- События смерти имеют устойчивый ID, повторяются до подтверждения и ограничиваются `storage.death_retention_seconds`.
- Клиент tMapOnline переподключается при разрыве. Listener хранит последнее состояние, чтобы новый клиент сразу получил актуальный snapshot.
- Web Map Ping отправляется как команда с координатами тайлов; мод выполняет игровую рассылку подключённым игрокам. Игровые Map Ping входят в обратный поток как события с координатами тайлов.
- Клиентские отображаемые настройки не пересылаются в мод. Интервалы и направленность пингов задаются конфигурацией запуска сервера.

Схему и endpoint-ы см. [telemetry.md](telemetry.md). Если поле меняет смысл или тип, используйте новую версию схемы и переходный период совместимости; не меняйте v1 молча.

## сборка

На macOS можно указать установленный каталог tModLoader через `TML_ROOT`:

```sh
TML_ROOT="/path/to/tModLoader" python3 tools/build-mod.py
```

Скрипт запускает `dotnet build` проекта `tmaponline/tmodloader/tMapOnline/tMapOnline.csproj` с отдельным временным HOME и копирует ровно один пакет в `dist/tMapOnline.tmod`. Это не перезаписывает файл работающего сервера. Версию и путь сборки сверяйте с используемой сервером версией tModLoader.

После сборки мод необходимо включить в серверном `Mods/enabled.json`; для активации требуется перезапуск сервера. Перед перезапуском всегда проверяйте онлайн игроков и не прерывайте подключённую игровую сессию. Эта документация не запускает установку и не перезапускает сервер.

## изменения мода

1. Найдите соответствующий игровой hook в `TMapOnlineSystem` и вынесите содержимое в существующий/новый collaborator с ясной ответственностью.
2. Прочитайте совместно producer и backend consumer для меняемого snapshot или команды.
3. Оставьте Terraria API на игровом потоке; фоновой задаче передавайте сериализованные данные.
4. Для устойчивого события обеспечьте ID, повтор до ack и тестирование восстановления после разрыва.
5. Соберите мод через `python3 tools/build-mod.py` с той версией tModLoader, под которую он будет использоваться.
6. Не копируйте собранный `.tmod` в профиль работающего сервера и не запускайте сервер без явного запроса на установку/перезапуск.
