# архитектура tMapOnline

разберёмся, из чего состоит tMapOnline и как игровые данные доходят до карты в браузере. Python-сервис принимает и хранит данные. через API он отдаёт их веб-карте, а серверный мод собирает их внутри tModLoader.

если представить проект как цепочку, получится так: Terraria сообщает сведения моду, мод отправляет их сервису, сервис готовит ответ, а браузер превращает ответ в карту и значки. ни браузер, ни Python-сервис не читают игровые объекты напрямую из памяти Terraria.

если коротко: мод читает игру, Python-сервис принимает данные, а браузер показывает их. API – это адреса, по которым браузер и сервис обмениваются данными. снимок состояния (snapshot) – запись о том, что происходило в игре в конкретный момент. кэш – сохранённая копия данных, чтобы не готовить их повторно.

## проекты и границы

```text
tMapOnline/                       # проект веб-карты, backend и мода
├── tmaponline/                  # Python package and owned tModLoader mod
│   ├── backend/       # запросы, ответы и раздача файлов интерфейса
│   ├── telemetry/     # соединение с игровым модом
│   ├── sprite_renderer/ # чтение игровых текстур и подготовка PNG-спрайтов
│   ├── web/
│   │   ├── src/       # редактируемые файлы интерфейса и карты
│   │   ├── assets/    # готовые файлы, которые создаёт сборка
│   │   ├── static/    # исходные картинки, шрифты и другие файлы интерфейса
│   │   └── world-map/ # HTML-страница, с которой начинается веб-карта
│   ├── tmodloader/
│   │   └── tMapOnline/ # исходники C#-мода для игрового сервера
│   ├── config.py      # чтение, проверка и значения по умолчанию для YAML
│   └── runtime.py     # запуск и остановка сервиса и игрового процесса
├── docs/                        # инструкции по проекту
├── tests/                       # автоматические проверки Python и веб-кода
├── tools/                       # команды сборки интерфейса и мода
├── config.example.yaml
├── package.json
└── pyproject.toml
```

`backend/http.py` принимает запросы браузера и выбирает нужный ответ. `backend/store.py` даёт остальным частям программы один общий способ работать с данными, не разбираясь, в каком именно файле они хранятся. в `backend/services/` обязанности разделены по темам: `player_history` – история игроков, `movement` – перемещения, `live_telemetry` – свежие игровые данные, `monitoring` – состояние сервера, `world_map` – карта.

общие форматы и постоянные значения лежат в `store_common.py`. в хранилище есть небольшие части кода, которые добавляют ему отдельные возможности; это позволяет не собирать всё в одном огромном классе. блокировки не дают двум задачам одновременно менять одни и те же данные. а кэш повторно использует недавно подготовленные результаты.

в JSONL каждое сообщение занимает отдельную строку. сервис проверяет его и превращает в модель из `models/telemetry.py` – структуру с заранее известными полями. внутри программы с ней проще работать и находить ошибки. на входе и выходе данные переводятся в привычный формат, который уже ожидают браузер и другие клиенты.

частоты обновления задаются в `config.yaml`, чтобы быстро движущиеся значки и большая карта не передавались одинаково часто. tModLoader отдельно отправляет позиции, сущности и цветные данные карты. между сообщениями мод хранит последнее значение каждой категории.

первый запрос `/api/world-map` возвращает метаданные – размер мира и описание доступных слоёв – без пиксельных чанков. чанк здесь означает прямоугольник готового изображения. полный JSON со всеми чанками можно запросить явно через `?tiles=0`, например для экспорта.

браузер рисует только те объекты, которые попали в видимую часть карты. для каждого такого игрока или объекта он создаёт HTML-элемент со спрайтом. когда ты двигаешь карту или меняешь масштаб, браузер пересчитывает, какие значки оставить на экране. это влияет только на отображение: NPC в игре от этого не появляется и не исчезает.

изображение карты разделено на уровни пирамиды: на дальнем масштабе используются маленькие обзорные фрагменты, а при приближении – более подробные. сервер отдаёт PNG-плитки до 256 × 256 пикселей и собирает ответ только из чанков, пересекающих запрошенную область. кэш хранит готовые PNG, чтобы при повторном запросе не собирать их снова. он ограничен количеством записей и общим объёмом 32 МиБ; в `/debug` видны попадания в кэш, вытеснения и время сборки.

Canvas – это поверхность браузера для рисования изображения. активными остаются не более 16 тайлов карты и 4 МиБ декодированных изображений. карта и маска исследования лежат на разных canvas, поэтому обновление маски не заставляет скачивать базовые изображения заново. при переключении уровня детализации старое изображение остаётся видимым, пока браузер загружает новое. дальние от экрана плитки не добавляются в DOM. полный набор данных читается только при явном экспорте.

текущие позиции, смерти, монеты и изменения блоков приходят через `/api/world-map/live`. SSE (Server-Sent Events) – способ держать HTTP-подключение открытым и получать новые сообщения с сервера без отдельного запроса на каждый объект. сервер отправляет сведения рядом с видимой областью и небольшим запасом, а браузер пересоздаёт подписку при заметном перемещении карты. слой монет запрашивается только при сильном приближении.

если блок изменился, сервер сохраняет обновлённые данные. браузер обновляет только изображение плитки, где находится этот блок. если одна координата меняется несколько раз до следующего обновления, используется последнее состояние. остальные плитки обновятся, когда пользователь до них дойдёт. панель `/debug` помогает увидеть, как часто приходят снимки, насколько свежие данные, сколько весит ответ и сколько занимает подготовка изображений.

`telemetry/stream.py` принимает newline-delimited JSON snapshots. мод собирает состояние сервера и отправляет его на localhost. Web не обращается к игровому процессу напрямую: он читает согласованный API.

### рендер спрайтов

`sprite_renderer/xnb_texture.py` проверяет заголовки XNB и читает их `Texture2D` RGBA-данные. сжатые XNB разворачиваются через `sprite_renderer/lzx.py`, включая 32-КБ кадры; внешний LZX-пакет и Java runtime не нужны. `PlayerSpriteRenderer`, `NpcSpriteRenderer` и `MapItemSpriteRenderer` отвечают за композицию аватаров, портретов NPC/боссов и иконок предметов. Pillow используется только как лёгкая граница чтения/записи PNG; кэширование и HTTP-адреса изображений остаются у `StatusStore`. мод tModLoader остаётся на C#.

для соответствия игровым маркерам реализация сверяется с декомпилированным кодом той же версии Terraria/tModLoader. крест смерти берётся из игрового ресурса `Content/Images/MapDeath.xnb`; метод `Main.DrawPlayerDeathMarker` рисует его по координатам `Player.lastDeathPostion`, с центрированием и масштабом карты. поэтому tMapOnline использует исходный спрайт без дополнительной тени или искусственной обводки. декомпиляция нужна разработчику для проверки поведения игры; она не входит в этот репозиторий и не нужна для запуска проекта.

### tModLoader: композиция и сервисы

поток телеметрии отправляет snapshot с конфигурируемой частотой игровых тиков. смерти захватываются через `Player.KillMe`, имеют уникальный ID и остаются в очереди мода до подтверждения после успешной записи Python-сервисом. Python применяет настраиваемый TTL к сохранённым меткам. направление игроков и NPC идёт в payload отдельно от позиции, чтобы UI мог повторить горизонтальное отражение спрайта из игры.

`TMapOnlineSystem` — lifecycle/composition root: подключает игровые хуки, создаёт сервисы и собирает JSON-снимок, сохраняя прежний JSONL/API-контракт. детали вынесены в объекты с ограниченной ответственностью:

Composition root (корень сборки) – главный объект, который создаёт другие объекты и соединяет их. сервис – отдельный помощник, отвечающий за одну часть работы. Hook (хук) – место, где игра вызывает код мода в ответ на событие, например изменение мира.

- `TelemetryStreamServer` владеет TCP listener, клиентами и доставкой последнего полного снимка;
- `WorldMapScanner` сканирует базовую карту по небольшому чанку за игровой тик, готовит палитру и сообщает прогресс;
- `PlayerMapChangeRevealer` строит область карты возле игрока и ограничивает повторный захват регионов;
- `MapTileDataCapture` сериализует ID блоков/стен и сжимает область;
- `MapTileNameCatalog` разрешает локализованные названия и постепенно отправляет их вместе с данными;
- `PlayerAppearanceSnapshotBuilder` собирает внешний вид игрока и экспортирует нужные текстуры;
- `WorldEntitySnapshotBuilder` собирает маркеры пилонов, NPC/боссов и выпавших монет;
- `BossProgressSnapshotReader` читает только ванильные флаги прогресса;
- `CalamityBossProgressAdapter` отдельно опрашивает необязательный Calamity-мод и его сохранённые флаги;
- `BossVictoryTracker` сохраняет повторные победы в формате `ApplicationData/tMapOnline/boss-victories.json`.

сервисам передаётся только то состояние, которое нужно для их работы. чтение и изменение `Main`, `Player`, `NPC`, тайлов, палитры и карты выполняется синхронно на игровом потоке. фоновый транспорт получает сериализованные неизменяемые строки JSONL, а не живые игровые объекты. `Main.dedServ` не подменяется ради инициализации карты.

## разбиение интерфейса

`web/world-map/index.html` — единственная точка входа веб-карты tMapOnline. `/` и `/world-map` открывают одну карту; старый экран мониторинга выключен. исходники оболочки, карты, разделов и стилей находятся в `web/src`. `npm run build` компилирует и минифицирует TypeScript в ES-модули и SCSS в CSS внутри `web/assets`. в production Python раздаёт готовые файлы и не требует Node.js.

`src/app-shell.ts` — объект `TMapOnlineApplication`: он загружает данные разделов по запросу и открывает их в пиксельном диалоге. карта сразу занимает весь экран. `MapActionMenu` строит вертикальные категории и соседнее подменю; `PixelModal` отвечает за закрытие, клавишу Escape и передачу фокуса клавиатуры нужной части окна. игроки и маршруты настраиваются из окна игроков и сразу обновляют слои карты. `MapZoomControls` соединяет пиксельные кнопки масштаба и обзор всего мира с контроллером карты. разделы `src/sections/{world,players,bosses,server,activity}.ts` загружаются динамически – только после открытия соответствующего пункта. их стили тоже загружаются лениво, то есть не заранее, а когда понадобятся.

категории карты содержат пункты игроков и маршрутов, данных мира и побед над боссами, сервера и активности; на `/debug` также доступна диагностика. разделы можно включать в `site.sections` конфигурации. Backend обслуживает их через отдельный компактный `/api/section-data?section=...`; прогресс боссов включает активных боссов, ванильные флаги побед, совместимый счётчик повторных побед и необязательный Calamity-статус. полноразмерный `/api/status` остаётся для совместимости и не используется как источник данных модальных окон. обновления карты продолжаются, пока открыто модальное окно.

UI использует нативные ES modules без frontend runtime и компонентной библиотеки. граница загрузки явная: оболочка отвечает за меню и модальные окна, SCSS секции — за её пиксельное оформление, `mount(root)` — за запрос и рендер данных. сборка через esbuild и Sass выполняется при разработке/пакетировании; аналитика, история игроков и журналы не загружаются, пока пользователь не откроет соответствующее окно.

### TypeScript: объекты и обязанности

`src/map/world-map.ts` остаётся точкой сборки страницы карты: он активирует конфигурируемые функции, связывает жизненный цикл данных с отображением и обновляет слой карты. отдельные объекты отвечают за изолированные механизмы:

- `MapSnapshotCache` — IndexedDB и восстановление сохранённого состояния;
- `MapChunkCodec` — распаковка и композиция базовых чанков и обновлений;
- `MapPyramidLayerRenderer` — выбор уровня детализации, загрузка видимых PNG-плиток, отмена устаревших HTTP-запросов при смене области и приоритет тайлов около точки масштабирования; без активной точки первым загружается центр viewport;
- `MapExplorationMask` — объединение импортированной карты и маршрутов в маску открытых областей;
- `MapImageExporter` — PNG-экспорт пиксельной карты с учётом включённой маски исследования;
- `MapViewportController` — масштабирование, перетаскивание, жесты и события viewport; передаёт мировую координату зума рендереру, чтобы запросить её тайлы первыми;
- `MapZoomControls` — кнопки изменения масштаба и возврата к масштабу всего мира;
- `MapEntityLayer` — маркеры игроков, NPC/боссов, монет, пилонов и точки появления; координаты вне видимой области не создают DOM-спрайты и анимационные циклы;
- `MapTooltipController` — задержка наведения, кэш информации о блоках и карточка подсказки;
- `MapPlayerPathService` — нормализация истории игрока, кэш маршрутов и разделение исследования на сегменты вокруг телепортаций;
- `MapRouteLayer` — SVG-маршруты и маркеры текущих позиций;
- `MapDiagnosticsPanel` — состояние сканера и диагностическая панель.

новый функционал карты следует добавлять в отдельный объект с одной ясной ролью и явными зависимостями через конструктор/связи. `world-map.ts` не должен снова забирать на себя кодек чанков, жизненный цикл IndexedDB, обработку жестов или разметку маркеров. оставшиеся крупные сценарии карты выделяются по мере изменения соответствующих функций; не создаём тонкие классы-обёртки без собственного состояния или поведения.

Frontend-команды: `npm ci` устанавливает закреплённый lock-файлом toolchain, `npm run typecheck` проверяет TypeScript, `npm run build` обновляет `web/assets`, `npm run check:web` выполняет обе операции подряд. после изменений исходников необходимо собрать assets до запуска или упаковки tMapOnline. Python-код проверяется Pyright в режиме `strict` (тот же движок использует Pylance): `npm run check:python`. для локальной среды установите `python3 -m pip install -r requirements-dev.txt`, затем `npm ci`. полная проверка — `npm run check:all`. в четырёх существующих сервисах с версионно-гибкими JSON-хранилищами отключены только диагностики неизвестных типов; используемые поля по-прежнему проверяются в рантайме, а остальной строгий набор Pyright включён.

## состояние и конфигурация

`config.yaml` — конфигурация запуска и включения страниц и разделов. клиентская тема, выбранные игроки/слои и положение карты хранятся отдельно в localStorage. персональные данные и кэши находятся в `~/Library/Application Support/tMapOnline`, не в репозитории. схему API и телеметрии см. в [telemetry.md](telemetry.md).

конфигурация отделяет запуск сервиса от включения страниц и компонентов; пользовательские настройки отображения хранятся отдельно от серверных параметров.
