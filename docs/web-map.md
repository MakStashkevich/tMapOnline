# веб-карта tMapOnline

этот документ объясняет, как устроена веб-карта. браузер получает карту и игровые данные от Python-сервиса, а не подключается к Terraria напрямую. tModLoader-мод передаёт сервису сведения об игре. сервис готовит из них API-ответы, изображения и историю.

ниже разобраны путь данных, кэш, слои карты и обязанности основных компонентов. слова «чанк» и «тайл» здесь означают разные вещи: тайл – один игровой квадрат Terraria, а чанк – прямоугольный кусок готового изображения, который браузер загружает отдельно.

## поток от API до пикселя

1. `web/src/map/world-map.ts` создаёт карту, подключает модули из `/api/site-config`, запрашивает метаданные мира и соединяет рендереры с контроллерами.
2. сервер отдаёт уже растеризованные PNG-фрагменты через `GET /api/world-map/tile?world=…&level=…&x=…&y=…`. браузер не пересылает RGB-массивы и не перекрашивает всю карту при каждом открытии.
3. `MapSnapshotCache` сохраняет клиентский снимок/чанки в IndexedDB. `MapPyramidLayerRenderer` держит грубый обзор и выбирает уровень детализации под текущий масштаб; видимые фрагменты имеют приоритет, устаревшие запросы отменяются.
4. `MapViewportController` преобразует колесо, pinch и перетаскивание в координаты области просмотра. мировая координата зума влияет на приоритет сетевых запросов.
5. отдельный лёгкий live-запрос обновляет игроков и сущности. карточки NPC, пилонов и прочих объектов идут отдельным DOM-слоем поверх изображения карты.
6. изменения тайлов приходят дельтами телеметрии, обновляют backend-хранилище и затрагивают соответствующие базовые и пирамидальные PNG-чанки.

здесь «рендерер» – часть программы, которая рисует данные; «контроллер» – часть, которая обрабатывает действия пользователя и координирует запросы. «Дельта» – маленькое сообщение только об изменениях, а не о всей карте.

слои карты обновляются независимо друг от друга. базовый слой – изображение мира. исследование – подсветка открытых мест. маска – чёрно-белое изображение, которое определяет, где этот слой виден. другие слои показывают текущие позиции, линии маршрутов, Map Ping, фон и кнопки интерфейса. если добавить новый слой, браузер должен получить его данные из API и передать компоненту, который его рисует. изменение одного слоя не должно заставлять заново загружать остальные.

## владение состоянием

| состояние                                                              | источник истины                     | переживает обновление страницы                        |
| ---------------------------------------------------------------------- | ----------------------------------- | ----------------------------------------------------- |
| серверные функции, интервалы сбора и срок истории маршрутов            | `config.yaml` и `/api/site-config`  | да                                                    |
| слои, плавность, частота отображения                                   | `localStorage` браузера             | да, в этом профиле браузера                           |
| фрагменты и состояние клиентского кэша                                 | IndexedDB браузера                  | да, пока браузер не удалит данные сайта               |
| исследованная карта, история игроков/сессий, события и прогресс боссов | файлы в каталоге данных tMapOnline  | да, независимо от браузера                            |
| Live-позиции и текущие NPC                                             | свежие снимки серверного мода       | нет: исчезают при остановке/потере свежести источника |
| текстуры карты/маски и PNG-пирамида                                    | backend-хранилище по миру и профилю | да                                                    |

`localStorage` – область небольших постоянных настроек браузера; `IndexedDB` – его хранилище для более крупных данных, например чанков. они принадлежат конкретному браузеру и устройству. поэтому другой телефон не получает их автоматически. каталог данных сервера – обычные файлы на компьютере, где запущен tMapOnline.

настройки видимости в вебе — пользовательские, не серверные и не синхронизируются между устройствами. конфигурация сервера может запретить слой целиком; пользовательский переключатель не может включить отключённую сервером возможность.

## основные компоненты

- `app-shell.ts` и `core/modules.ts`: меню, конфигурируемые действия/разделы и общие точки подключения.
- `components/map-display-settings.ts`: локальные предпочтения карты и уведомление об изменении настроек.
- `components/map-action-menu.ts`, `components/pixel-modal.ts`, `components/map-zoom-controls.ts`: общие визуальные/поведенческие элементы меню и модалок.
- `map/world-map.ts`: composition root карты; не должен повторно забирать на себя кодек чанков, жесты, кэш и все DOM-слои.
- `map/map-snapshot-cache.ts`, `map/map-tile-bitmap-cache.ts`, `map/map-tile-pyramid-renderer.ts`: получение и кэширование изображения.
- `map/map-viewport-controller.ts`: координатные преобразования, жесты, масштаб и запрос видимых областей.
- `map/map-entity-layer.ts` и `map/map-tooltip-controller.ts`: живые маркеры и игровые подсказки.
- `map/map-player-path-service.ts`, `map/map-route-layer.ts`, `map/map-exploration-mask.ts`: выбор маршрутов, маски исследования и линии.

Composition root – объект, который создаёт компоненты и соединяет их друг с другом. кодек – программа для упаковки и распаковки данных. названия файлов проверяйте поиском по `web/src`: файл может переехать, но обязанность каждого компонента должна оставаться узкой и понятной.

## производительность и Safari/iOS

- не создавать гигантский canvas/bitmap размером всего мира в момент зума. работать по видимым чанкам и держать грубый слой до готовности подробных.
- не очищать уже отрисованный слой при смене уровня детализации: показывать старый/грубый bitmap до прихода нового, чтобы не получить вспышку пустого фона.
- отменять устаревшие запросы и не применять ответы старого viewport к новой области. при pinch приоритетно загружать чанки около центра жеста.
- стабилизировать размеры и transform слоёв/маркеров на протяжении pinch-анимации. не удалять и не создавать заново DOM-спрайты NPC при каждом изменении zoom.
- использовать разумные пределы размера bitmap и не делать копии больших массивов пикселей без нужды: лимиты iOS Safari отличаются от настольного браузера.
- после изменений в этой области отдельно проверить ручной zoom и pinch в Safari iOS; успешная сборка сама по себе не доказывает отсутствие мерцания на телефоне.

## как менять карту

1. найди, откуда страница загружает данные, и проследи путь до API и кэша.
2. сохраняйте карты больших размеров лениво: API по viewport, кэш по миру/версии/профилю/уровню/координатам.
3. данные большого размера запрашивайте отдельно от компактного live-снимка. не добавляйте полную историю в частый polling.
4. настройки пользователя храните в браузере; серверные интервалы, доступность функций и сроки истории — в серверном конфиге.
5. для нового UI используйте переиспользуемый компонент, существующие пиксельные токены и клавиатурную/мобильную семантику.
6. при изменении протокола обновляйте вместе TypeScript consumer, backend handler/store и мод producer.
7. после TypeScript/SCSS правок пересоберите assets; см. `npm run build`.

## ограничения текущей карты

изображение передаётся PNG чанками. тайловые массивы остаются серверным источником и нужны для перегенерации изображения и подсказок. неразведённая область не раскрывает настоящий мир клиенту: она маскируется на стороне сервера. Live-сущности зависят от свежих снимков мода; устаревший снимок считается непригодным для отображения координат.
